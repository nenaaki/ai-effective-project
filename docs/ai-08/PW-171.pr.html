概要

トップメニュー（/）に実装されていた「配送日変更リスト」と「未配車リスト」の各パネルを、「準備中」プレースホルダから実際のコンポーネントへ差し替えた。配送日変更リストのロジックをページから再利用可能な ReschedulePanel コンポーネントとして抽出し、フルページ（/notifications/reschedule）とトップメニューパネルの両方から利用できる形に統一した。未配車リストはDispatchドロワー内のサマリテーブルを再利用する形でパネルに埋め込んだ。

背景・目的

トップメニューでは「配送日変更リスト」「未配車リスト」の各チェックボックスをONにするとパネルが展開されるが、PW-171 以前はいずれも「準備中」テキストを表示するプレースホルダのみだった。本PRにより、これらのパネルに実際のコンテンツを組み込む。

あわせて、配送日変更リストページ（/notifications/reschedule）にページコンポーネントとして直書きされていたすべてのロジックを ReschedulePanel に集約し、ロジックの重複とタイトルの二重表示を解消するリファクタリングを実施した。

  • 関連チケット: PW-171

変更点

フロントエンド（管理画面）

ReschedulePanel の新規作成と利用

  • features/tms/reschedule/components/reschedule-panel.tsx を新規作成した。BatchLogPanel と同設計で、props として newCount / defaultItemsPerPage / perPageOptions / showSearch を受け取る。
  • features/tms/reschedule/components/index.ts を新規作成し、RescheduleSearchForm / RescheduleTable / ReschedulePanel をまとめて再エクスポートするようにした。
  • pages/notifications/reschedule.tsx のすべてのロジック（GraphQL クエリ・ミューテーション・状態管理・ハンドラ）を ReschedulePanel に移動し、ページはパネルを呼ぶだけのシンプルな構造に変更した。これによりページ独自ヘッダとパネルヘッダのタイトル二重表示も解消した。
  • features/tms/top-menu/components/delivery-date-change-panel.tsx で「準備中」テキストを <ReschedulePanel defaultItemsPerPage={5} perPageOptions={[5, 20, 50, 100]} showSearch={false} /> に差し替えた。

UnassignedSummaryTable の再利用

  • features/tms/dispatch/components/UnassignedListContent.tsx の UnassignedSummaryTable を export に変更し、Dispatchドロワー外から利用できるようにした。
  • features/tms/top-menu/components/unassigned-deliveries-panel.tsx で「準備中」テキストを <UnassignedSummaryTable /> に差し替えた。集計API（PW-144_3）が未実装のため、テーブルヘッダーは表示されるがデータ行は空の状態となる（Dispatchドロワー側と同じ挙動）。

画面別テストチェックリスト

1. 管理画面トップ（/）— 配送日変更リストパネル

影響の原因: DeliveryDateChangePanel の中身が「準備中」テキスト → <ReschedulePanel defaultItemsPerPage={5} perPageOptions={[5, 20, 50, 100]} showSearch={false} /> に差し替え

  • トップメニュー（/）を開き、「配送日変更リスト」チェックボックスをONにする → パネルが表示され「準備中」文字列が消えていること
  • 表示されたパネルに「配送日変更リスト」のタイトルヘッダーが表示されること
  • 検索フォームエリアが表示されていないこと（showSearch=false の確認）
  • データ行が存在する場合、1ページ5件で表示されること（defaultItemsPerPage=5）
  • ページネーションのページサイズ選択肢が「5、20、50、100」であること
  • データ行のいずれかをクリックし、配送詳細ドロワーが開くこと
  • 未読行をクリックしてドロワーを開いた場合、「既読にする」ボタンが表示されること
  • 「既読にする」ボタンをクリックすると成功トーストが表示され、行のステータスが更新されること（refetch）
  • 既読行をクリックした場合、「既読にする」ボタンが表示されないこと
  • ページネーションでページを切り替えると、表示件数が更新されること
  • エラー時（APIエラー）にエラーメッセージエリアが表示されること

2. 管理画面トップ（/）— 未配車リストパネル

影響の原因: UnassignedDeliveriesPanel の中身が「準備中」テキスト → <UnassignedSummaryTable /> に差し替え

  • トップメニュー（/）を開き、「未配車リスト」チェックボックスをONにする → パネルが表示され「準備中」文字列が消えていること
  • パネル内にサマリテーブルのヘッダー行が表示されること（「No.」「デポ名」「エリア名」「午前中」「12:00-14:00」「14:00-16:00」「16:00-18:00」「18:00-21:00」「指定なし」の各列）
  • テーブルのデータ行が空（tbody が空白）であること（PW-144_3 集計API未実装のため意図された状態）

3. 管理画面 配送日変更リスト（/notifications/reschedule）— リファクタ後の動作確認

影響の原因: ページ内に直書きされていた全ロジックを ReschedulePanel に抽出。ページは <ReschedulePanel /> を呼ぶだけになった。defaultItemsPerPage=20、perPageOptions=[20, 50, 100]、showSearch=true（いずれもデフォルト値）。

  • /notifications/reschedule を開き、「配送日変更リスト」のタイトルと検索フォームが表示されること
  • 検索フォームが初期表示で展開状態（isSearchFormOpen=true）であること
  • 検索フォームの折りたたみトグルボタンをクリックすると、検索フォームが折りたたまれ・展開されること
  • 検索フォームのデポ選択肢にデポ一覧が表示されること
  • 検索条件（デポ・エリア・配送予定日範囲など）を入力して「検索」ボタンを押すと、一覧が絞り込まれること
  • データ行が存在する場合、1ページ20件で表示されること
  • ページネーションのページサイズ選択肢が「20、50、100」であること（5 は含まれないこと）
  • ソートアイコンをクリックすると昇順 → 降順 → 解除の3段階でソートされること
  • 行クリックで配送詳細ドロワーが開くこと
  • 未読行のドロワーで「既読にする」が機能すること（一覧の既読表示が切り替わる）
  • コンソールエラー・JSエラーが発生していないこと（リファクタ前後で挙動に差がないこと）

4. 管理画面 配車ドロワー（/dispatch）— 既存の未配車情報タブへの非影響確認

影響の原因: UnassignedListContent.tsx 内の UnassignedSummaryTable を export に変えた。UnassignedListContent コンポーネント自体は変わっておらず、dispatch ページへの影響は想定されないが、export 変更による import 解決の問題がないことを確認する。

  • /dispatch を開き、配車ドロワー内の「未配車情報」タブが正常に表示されること（テーブル・検索フォームが崩れていないこと）
  • コンソールエラーが発生していないこと

スコープ外（変更の影響なし）

  • ドライバーアプリ全般: フロントエンド変更が管理画面のみに閉じており、ドライバーアプリへの変更はない
  • API（api-core）全般: API / DB変更なし。既存の Query / Mutation の挙動は変わらない
  • 管理画面のその他のページ: SEARCH_DELIVERY_MEMOS / MARK_DELIVERY_MEMO_AS_READ / SEARCH_M_DEPOTS を使用しているのは reschedule 系画面のみであり、他ページへの波及はない
  • BatchLogPanel / BulletinPanel（トップメニュー内他パネル）: コンポーネント自体に変更なし。チェックボックスのロジック（最大3件制限など）も変更なし

補足・注意事項

  1. SEARCH_M_DEPOTS の無駄クエリ: ReschedulePanel は showSearch=false でも useQuery(SEARCH_M_DEPOTS) がマウント時に発行される。トップメニューの「配送日変更リスト」パネルでも余分なデポ一覧クエリが飛ぶ。機能上の問題は出ないが、開発者ツールのネットワークタブで確認した際に意図的であることを把握しておくこと。
  2. 未配車リストのデータ行が空であることは仕様: UnassignedSummaryTable の tbody は集計API（PW-144_3）が実装されるまで空のまま。「データが表示されない」はバグではない。
  3. 配送日変更リストページのリファクタは純粋な移動: /notifications/reschedule の全ロジックが ReschedulePanel に移動したが、機能追加・変更はない。リファクタ前後で画面の見た目・動作に差がないことを確認することが主眼。

設計レーンとテストレーンの整合性・進行・追跡を担う。フェーズに紐づかず常時稼働。
Orchestrator（オーケストレーター）
各フェーズの AI エージェントへタスク投入、依存関係に基づく順序制御、PR 作成、ゲート判定の起票。 上流（要件・基本設計）の更新を検知して下流テストレーンへ波及させる。

トレーサビリティAINEW後回し

人タスク（エンジニア／PM／業務SME の役割）
AI による派生は「素案」であり、業務知識を持つ人が最終承認する。V字の各レイヤで担当が異なる。
▲ 人が担う Check ポイント（AI には委ねきれない承認・判断）
要件 / 受入
業務SME による受入基準の妥当性確認・最終承認。
＝ 業務的に正しいかは人にしか判断できない
基本 / システムテスト

実装 / 単体テスト
コードレビュー（仕様適合・セキュリティ・設計整合）、PR マージゲート判定。

エスカレーション経路（V字フロー上で失敗した時にどこへ戻すか）
テスト失敗の原因がどの層に起因するかで差し戻し先が変わる。AI が原因層を推定し、Orchestrator が起票する。
失敗が発生したブロック・状況 差し戻し先・対応
単体テスト NG（実装バグ） 実装 へ差し戻し（ai-04 の AI Orchestration 内で再実装）
結合テスト NG（モジュール間契約不整合） 詳細設計 へ差し戻し（API 契約・データモデルを修正 → 実装再生成）
システムテスト NG（性能・機能間連携・非機能） 基本設計 へ差し戻し（非機能設計や I/F 設計を見直し）
受入テスト NG（業務シナリオ不一致・要件解釈ミス） 要件定義 へ差し戻し（業務SME と要件を再確認 → 下流へ波及）
テスト仕様派生AIが要件・設計の曖昧さを検出 対応する上位の設計フェーズへ即時起票（テスト作成を保留）

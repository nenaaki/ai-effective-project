5. パイプライン全体評価

✅ 良かった点

  • end-to-end が初回で通った（60 シナリオ・10 起票候補）
  • usecase-formatting-ai が責務（Given-When-Then 出力禁止）を厳守
  • spec-consistency-reviewer-ai が ISSUE-001/002 を事後検出に成功（自浄作用が機能）
  • business-rule-extraction-ai と glossary-generation-ai の並列実行可能を確認
  • 各エージェントが建設的な改善提案を返した

❌ 改善すべき点

  • id-assignment-engine / atomic-requirement-ai / business-rule-extraction-ai / glossary-generation-ai が入力境界を超えて補助資料を参照する自律判断（PW-115 の推測補完問題の再現）
  • acceptance-test-design-ai が未定義事項を独断で具体化（mock 逸脱と同じ構造）
  • spec-consistency-reviewer-ai と acceptance-test-design-ai の実行順序を usecase-formatting-ai → spec-consistency-reviewer-ai → acceptance-test-design-ai に揃える必要
  • business-rule-extraction-ai の YAML 出力品質保証が必要（lint）
  • id-assignment-engine と atomic-requirement-ai の ID 粒度設計の統一が必要

6. エージェント定義への改修提案

エージェント改修内容
id-assignment-engine「見出しを要件文として採番しない」を責務境界に明記。要件文が無い場合はエラー停止
atomic-requirement-ai「上流出力以外は読まない」を厳格化。上流の品質不足はエラーで返す
business-rule-extraction-ai出力 YAML を yamllint で検証するステップを workflow に追加
glossary-generation-ai補助資料参照は許可するが、参照範囲を inputs/ に限定明記
acceptance-test-design-ai「未定義事項を独断で具体化しない」を責務境界に明記。具体化は必ず未充足レポートへ移動
spec-consistency-reviewer-ai「Gherkin の独断具体化」「mock に無い項目の追加」を検出パターンとして追加
全エージェントフロントマターに「補助資料の参照可否」フィールドを追加し、明示的に制御

7. パイプライン順序の見直し

現状

chapter-structuring-ai → id-assignment-engine → atomic-requirement-ai → business-rule-extraction-ai
+ glossary-generation-ai → usecase-formatting-ai → acceptance-test-design-ai → spec-consistency-reviewer-ai

推奨

chapter-structuring-ai → id-assignment-engine → atomic-requirement-ai → business-rule-extraction-ai
+ glossary-generation-ai → usecase-formatting-ai → spec-consistency-reviewer-ai
（中間レビュー） → acceptance-test-design-ai → spec-consistency-reviewer-ai
（最終レビュー）

usecase-formatting-ai → spec-consistency-reviewer-ai → acceptance-test-design-ai の順にすることで、ISSUE-001/002 のような独断具体化を Gherkin 生成前に防止できる。

  • 相談済み課題事例⑥: AIの「最後の2%」修正の属人性（クローズ → ⑧へ移譲）
    AIが98%作った後の残り2%を100%にする工程の属人性。「30分かかる」と「人が直すと壊れる」は同じ現象の裏表で、指示の3点セット（場所・あるべき姿・証拠）が欠けるとAIは全体を探索し契約を誤解して壊す。属人性の正体はAI側でなく人間の指示スキル（暗黙知）。熟練者の型を抽出＝①動かして気づく②通り道を遡る(画面→API→DB→データ)③指示/詰問④違和感を言語化。打ち手は【抑止】と【対応】の両輪（2%はゼロにできない前提）。抑止＝②③をAIに肩代わり＝実装AIが「画面項目→table.column→実データ?」を自己申告し、レビューAIがPrismaスキーマ(SSOT)・実APIと敵対的検証、DB非依拠の仮値は有罪推定で却下・出所不明なら停止し率直に報告。対応＝すり抜けた2%（契約誤り/振る舞い/違和感）を出口検収で検知し、3点セットで速く壊さず直す→修正後に経路報告を再実行して抑止ゲートを各修正にも巻くループ／社長案「別AIに分離」は30分が続いた時の脱出弁として吸収。人に残るのは①習慣と④違和感のみ（完璧にはならない）
    【クローズ】以降の検討は課題事例⑧に移譲。⑥の「デバッグの改善」ループはセッションログから誤解を抽出して積む前提だったが、⑧ではAIの自己申告は事後作話になりうるため、再現テストで裏取りした因果だけを積む方針に改めている。

  • 相談済み課題事例⑧: デバッグ（残り2%）の逆方向探索 — 遡れる場所へ問題を移す（⑥から継承）
    7/30 MTG「逆方向の探索」の具体化。前提の置き換え＝AIの内部は原理的に遡れない（順伝播は非可逆な情報圧縮／IF-THEN的な離散の分岐点が存在しない／アテンション可視化・メカニスティック可解釈性・Causal Tracing はモデル内部の活性値にアクセスできる立場の技術でAPI越しの我々には使えない）。帰結として「なぜそう判断したか」への回答は事後作話であり、セッションログをそのまま積むと検証不能な情報が増える。一方コードとテストは決定論的で完全に遡行可能なので、説明変数を外部に取り出せるものだけ（入力コンテキスト／実装前に明文化させた前提・仕様解釈／git diff／テストケース／実行結果）に定義し直す。肝は「AIが置いた前提を実装前に外に出させる」こと。手法の翻訳＝内部解析の3手法をプロセスに移植＝①反実仮想（「なぜそうしたか」でなく「入力のどこが変われば結果が変わるか」を問う＝問い方テンプレートの核）②介入実験＝仕様記述を抜く/変える/足して再生成し「AIの誤解」か「仕様の欠陥」かを割る③差分の二分探索＝変更を分割適用して真因の物理的位置を特定（AIの推測を介さないため最も信頼でき自動化価値が最大）。切り分けの第一手は再現性そのものを診断に使う（毎回同じ間違い＝仕様の欠陥／毎回違う＝指示が曖昧・情報不足）。運用＝ナレッジベースは再現テストが「落ちた→直った」で裏取りした（症状→真因→修正）のみ蓄積し、修正前に失敗する再現テストを書かせるのを前提条件にする（テストが真偽判定を担う＝AIの説明の正しさに依存しない）。着手順＝①反実仮想型テンプレート②再現性チェック③再現テスト先行の明文化④差分二分探索の自動化。要点は「AIの中は遡れない。だから遡れる場所（コード・テスト・差分）に問題を移してから遡る」。

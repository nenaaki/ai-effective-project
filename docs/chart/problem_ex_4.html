品質管理プロセスと承認権限: シナリオ／作業チケットの進め方

2026-07-09 議題③の整理 / 左＝汎用プロセス、右＝運送業シナリオ（持出・配送完了）への当てはめ
総括管理者の仕事は「進捗管理」ではなく 作るものの正しさ（スコープ）を保証 すること。完了条件は AI にドラフトさせて人間が調整し、承認は 権限を持つ管理者 が行う。

プロセス（起票 → 合意 → 実装 → 承認）

⚠ 変更管理の場合の注意点
既存実装と相互影響がある場合、④の実装中に見つかった影響範囲から、新たなテスト観点を追加すべきことがある。 その場合も、追加するテスト観点をPM × エンジニアで合意し、チケットに付け加える。

ドラフトチケットの例

notice-list-role-access課題
お知らせ一覧のロール別 表示範囲の出し分け

概要

  • トップメニューの「お知らせ一覧」は、ログインユーザーのロール（権限グループ）に応じて表示範囲を出し分ける。
    • システム管理者や物流本部の運用管理者には全件を見せ、デポ運行管理者やOEM先・KSLの運用管理者には自分の担当範囲（自デポ／自荷主）に関係するお知らせだけを見せ、サーバー管理部やカスタマーサポートなどお知らせを見る立場にないロールには一覧そのものを見せない。本チケットでは、この「どのロールに・何を・どの範囲まで見せる／見せないか」を業務仕様を合意したのち実装する。
  • 権限グループごとのアクセス可否・範囲を管理する認可基盤に対して、「お知らせ一覧」向けの設定（ロールごとの許可範囲）を確定することが本チケットの目的である。ルート保護やAPI側の絞り込み処理そのものの実装は別スコープとする。

内容

実現したいこと（何を作るか）:

トップメニューの「お知らせ一覧」を、ログインユーザーのロールに応じて「全件」「自デポのみ」「自荷主のみ」「非表示」を出し分けられるようにする。

実装範囲（シナリオ上の作用・正常系／異常系）:

シナリオ: ユーザーがトップメニューを開くと、自分のロールに応じた範囲のお知らせエリアが表示される（画面遷移は発生せず、既存お知らせエリアの表示内容が変わるのみ）。

区分ケース期待挙動
正常系全件ロールが開く掲載期間内の全お知らせが表示される
正常系自デポ／自荷主ロールが開く自分の担当範囲が掲載対象のお知らせのみ表示される
正常系添付ファイル付きお知らせ閲覧可能な範囲内であればダウンロードできる
異常・境界禁止ロールが開くお知らせエリアが表示されない
異常・境界担当範囲に一致する掲載対象が無いスコープ限定ロールには1件も表示されない（0件）
異常・境界自デポ／自荷主ロールで所属デポ・所属荷主が未設定0件（便宜上の全件表示はしない）
異常・境界掲載期間外（開始前・終了後）ロールに関わらず表示されない（既存挙動を維持）
作り方の方針（合意すべき範囲・前提）:
項目方針
対象画面管理画面トップメニューの「お知らせ」エリア（一覧閲覧・行クリックでの詳細表示）
APIによる情報の保護ユーザーのロール（全体／自荷主のみ／自デポのみ／禁止）によって、APIはアクセス可能なスコープを絞り込む。「お知らせ」のアクセスすべてが対象となる（APIの実装修正で実現）
画面上の保護ユーザーのロール（禁止）によって「お知らせ」エリアの表示制御を行う（コンポーネント認可基盤を使用する）
既存の作りへの合わせ方ログインユーザーの権限グループごとにアクセス可否・範囲（全体／自荷主のみ／自デポのみ／禁止）を管理する既存の権限項目と同じ考え方に揃える。
前提（基盤に委ねる）ルート保護・権限判定の実行時の仕組み・API側の絞り込み処理そのものは、別途整備される認可基盤に委ねる。本チケットはその基盤に「お知らせ一覧」用に設定すべき内容（ロールごとの許可範囲）を確定することが目的
スコープ外（やらないこと）:
  • 権限判定基盤・ルートガード・API認可処理そのものの実装
  • お知らせ一覧の列構成・ページング件数・ソート順など表示フォーマットの変更（今回はロールによる出し分けのみ）
  • お知らせ登録画面（掲載対象の設定UI）の変更（下記論点で扱うのみ。対応要否は別途判断）

要確認事項（合意が必要な論点）

各論点は現状値を提示済み。回答欄に記入してください。

#論点現状回答
1「自荷主のみ」ロール（OEM先運用管理者〈管理者用〉、KSL運用管理者）は、「掲載対象デポが、そのユーザーの所属荷主に属するデポであれば表示」という間接判定でよいかお知らせの掲載対象は「デポ」単位のみ設定でき、「荷主」を直接指定する項目は無い☐ Yes ／ ☐ No
2「非表示（禁止）」ロールでトップメニューを開いた場合、他パネル（帳票作成通知・デポ掲示板等）は通常表示され、お知らせエリアだけが非表示になる理解でよいかお知らせエリアは全ロール共通で常時表示される専用セクション（他の切り替え式パネルとは別枠）☐ Yes ／ ☐ No
3コールセンターオペレーター（地域配送CC委託先用）は社内ロール同様「全件表示」でよいか（委託先でも掲載対象による絞り込みは行わない）マトリクス表では「許可」と明記☐ Yes ／ ☐ No
4複数デポ・複数荷主に所属するユーザーは、いずれか1つでも掲載対象に一致すれば表示される（OR判定）理解でよいか―☐ Yes ／ ☐ No
5「自デポのみ／自荷主のみ」ロールに所属デポ・所属荷主が1件も設定されていない場合の挙動は0件表示で良いか―☐ Yes ／ ☐ No

完了条件（受け入れ観点｜目的トレース）

各項目を1件ずつ確認してチェックする（全項目が完了でマージ可）。テストデータは下記「テストデータ設計と期待表示マトリクス」を用いる。チェックの際は、エビデンスとしてスクリーンショットと、実際に用いたユーザーの「ユーザーID」を各項目に追記してからチェックすること。

  • 【全件】U1（全件ロール）でログイン → 掲載期間内の全お知らせ5件（N1・N2・N3・N4・N6）が表示される
  • 【自デポ】U2（自デポ{D1}）でログイン → N1・N4の2件のみ表示され、N2・N3・N6は表示されない
  • 【自荷主】U3（自荷主{S1}）でログイン → N1・N2・N4・N6の4件が表示され、N3は表示されない
  • 【複数所属OR】U5（自デポ{D1, D3}）でログイン → N1・N3・N4・N6の4件が表示される
  • 【禁止】U4（禁止ロール）でログイン → お知らせエリア自体が表示されない（他パネルは通常表示される）
  • 【未設定は0件】U6（自荷主・所属未設定）でログイン → お知らせエリアは表示されるが中身は0件
  • 【添付ダウンロード】表示可能なロールでN4を開く → 添付ファイルをダウンロードできる
  • 【掲載期間ガード】どのロールでもN5（掲載期間外）は表示されない
テストデータ設計と期待表示マトリクス

「許可（全件）／自デポのみ／自荷主のみ／禁止」を一意に判定するためのテストデータ。下の期待表示マトリクスが唯一の合格基準とする。

関係の前提

  • お知らせ ↔ デポ: 多対多（1つのお知らせに複数の掲載対象デポを設定できる）
  • デポ → 荷主: 多対1（デポは1つの荷主に属する）
  • ユーザー ↔ デポ / ユーザー ↔ 荷主: いずれも多対多
  • 判定: 自デポのみ＝「お知らせの掲載対象デポ ∩ ユーザーの所属デポ」があれば表示／自荷主のみ＝「掲載対象デポの荷主 ∩ ユーザーの所属荷主」があれば表示

この設計が保証すること（切り分けの根拠）

  • N2: U2(自デポ)✗・U3(自荷主)✓ → 「自デポ」と「自荷主」の取り違えを検出（D2はS1配下だがU2の所属デポではない）。
  • N3: U1(全件)のみ✓・U3(自荷主S1)✗ → 「全件」と「自荷主」の混同を検出。
  • N6: 1件のお知らせが複数デポ・複数荷主にまたがるケース。U2(D1のみ)✗・U3(S1経由でD2に一致)✓・U5(D3を所持)✓ → 交差判定とOR判定（論点4）を同時検証。
  • N4: 表示可能な各ユーザーで添付ダウンロードまで確認。
  • N5: 全ロール✗ → 権限と独立した掲載期間ガードの維持。
  • U4 と U6 の違い（重要）: 表示件数はどちらも0だが意味が異なる。U4（禁止）はお知らせエリアごと非表示、U6（自荷主・未設定）はエリアは表示されるが中身が0件。テストではこの2つを取り違えないこと。

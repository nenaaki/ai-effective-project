# エンジニアのマインドセットを総合職に向上するトレーニングキットとしてのAI駆動

これまでのイテレーションはAI駆動開発の強化を目的に据えていたが、イテレーション3からは目指すものとゴールを変える必要があると考えた。

- 報告軸：毎イテレーションで示す3点＋持ち越し

## 大目標：会社の成長に貢献するAI駆動開発チーム

- 個人の作業効率ではなく、会社の成長に効く単位で成果を出す
- 全社の個々のエンジニアを、プレイヤーからマネージャー（総合職）へ
- 対応できなければ価値を失う変化。会社は振るい落とさず、適応・成長させる方針なので、チームはそれに呼応する

## AI駆動の条件：大目標の3行が要求すること

- 成長単位：効果が案件単位で出る。個人の作業が速くなるだけでは足りない
- 成長単位：効果が工期・原価の数字として出せる（AsIs／ToBe、EVM）
- 総合職化：道具ではなく部下の形。依頼を受け、決められないことは質問で返す
- 総合職化：根拠を出し、コードを読まずにレビューできる。人の言葉の指摘で直る
- 総合職化：プロンプト技術を要求しない。何を作るか・完了条件の判断は人に残す
- 振るい落とさない：渡した相手がキャッチアップコストで止まらない（N社案件で出た懸念）
- 振るい落とさない：収束しない時は人手の設計開発へ戻す出口を持つ

## 2026下期：案件をまたいで通り、効果を数字で示せる状態

- 設計以降の型が複数カテゴリにそろい、担当エンジニアが実装をAIに任せ、指示とレビューで完了まで運べている（最後の仕上げは人がやる）
- キットが案件をまたいで通り、全社標準として横展開できる状態になっている
- 工数と経済効果を数字で示し、12月の全社会議で部長陣に提示できている

## イテレーション3：仮想部下パターンと使い方のトライ・検証

- 認証認可パターンで、仮想部下として回るエージェントを組んで試す
- PW以外（N社案件）で通る形にする

## 継続作業：AI駆動開発キットの整備（週次報告）

- 週次でPDCAの進みを報告し、イテレーション1つで一巡させる
- P 計画：AI側は道具から部下へ、イテレーション内選定したスコープをこの形に近づける。少なくとも1つ完成形の型を出す
- D 実行：仕様と指示を渡し、不足分のバイブコーディングのログから部下としての振る舞い・技術への対応を抽出する
- C 評価：出す前に4条件（定石で埋める・質問で返す・根拠を出す・指摘で直る）を満たすか見る
- A 改善：腕前に依存するものは出さず、収束しないものは人手へ戻して型を作り直す

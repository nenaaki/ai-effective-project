加えるべきもの

加えるべきものは3つ

いずれも思考過程を残すものではない。切れているリンクを1本ずつ繋ぎ直すだけ。A と C が本体で、B は別軸。

加えるもの直すリンクAs-Is（現状）To-Be（改善後）
A探索の機械化スキルとして実装 探索そのもの束ねる工程 経路を毎回手作業で辿る。ログ全体を都度走査し、辿り方も探す人によって違う。外れたら最初からやり直しで、この往復に上限が無い 入力はファイルの1行か、テストケースIDの1つだけ。0.2〜1.4 秒で、いつも同じ形の材料がまとまって出る。解釈は AI・判断は人に分業が固定される
B暫定実装に ID規約・対象を限定 回答後の差し替えデバッグ用ではない 未確定の論点に依存する暫定実装が、回答が来たときにどこにあるか分からない 未確定に依存する箇所だけに不明点 ID をコメントする
Ctrace に列を1つ書式 判断 → コード当たり外れの解消 「決めたこと」が業務語のみ。どのファイルに落ちたか書かれておらず、trace に当たるかは運 「落ちた先（ファイル / シンボル）」列を追加。なぜへの到達が確実になる

残すのは思考ではない

実際に効いたのは推論の流れではなく、「決めたこと」と「選ばなかった解釈」の2文だった。1 判断あたり 1 行で足りる。

なぜ 3 つで足りるのか

放っておいても残る分と、どうやっても残らない分は動かせない。動かせるのは前ページの △ 2 本だけで、A と C がそこを潰す。

trace は使い捨てでよい

寿命はその部分のデバッグが終わるまで。引き継ぎ資産ではないので、量を気にせず厚く書いてよく、.work/ が git 管理外でも支障は無い。残すのは、回答待ちとして起票した業務論点だけ。

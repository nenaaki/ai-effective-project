# 2%バグ問題：実装パターンを調整の報告

先週までに「準備していたやり方」ではうまくいかないケースがあったため、対策と現在検証していることを報告します

## 準備していたやり方とは何か

- 「実装前に設計を詰め切って」「リバース設計をレビューする」型でのAI駆動実装
- 先週受けた指摘：永遠に完成しないループから抜ける仕掛けが必要
（部分の完成が統合的な完全とならない場合に対応するため）

## 結果

- 成功：CSV出力を非同期出力基盤に組み込む実装
- 失敗：開発中期以降のデータモデル変更。インフラ制約が絡むもの
  - 原因：人間側のキャパ限界を超えてしまうため。設計に矛盾が残ったり、設計が終わらなかったりした

## 次の方針

- 実装前の設計密度を軽量化 → 仮実装＋機能テスト → 設計を逆算 → 人が指摘 → リファクタ
- 3周回して完了 or 非完了を判断する（完了しない場合は離脱：AIアシストに切り替える）

- ただし、インフラの変更、スキーマの変更など、ブレてはいけない部分は「実装前の設計」で詰め切る

課題事例: 要件不明確時のフローが整理されていない

AIDD 試行で見つかった構造的課題 / PW-120 デポマスタ試行で発見 / 2026-05-26

現状フロー（planner で不明検知時）

課題と論点

課題
業務判断が不明、もしくは要件不足により
確認したいことが発生した場合の導線が不明
論点
1
不明点が見つかった場合、停止するか / 不明点以外の実装を進めるか
2
不明点を解消するための確認チャネルはどう設計するか
3
不明点をどう管理するか
4
回答があったものをどう組み込むか

planner が現状できる確認

  • 人間からの指示に必要項目が揃っているか — 不足があれば停止し追記を要求
  • 画面設計と API スキーマの突合 — API 未実装のフィールド / 操作を検出し、後工程に切り出し
  • 入力制約（必須・最大長・形式）の抽出 — 既存の DTO 定義から自動取り込み
  • 業務要件書と画面設計の不整合検出 — 仕様の食い違いを一覧化。重大なら停止して人間確認
  • テスト要件が定義できない箇所の検知 — 業務判断未確定として記録
  • 画面実装に必要な情報の網羅チェック — 必要 9 項目（ビジュアル / ルーティング / API / マッピング / 表示変換 / 操作 / 確認待ち事項 / 入力制約 / テスト要件）が揃っているか

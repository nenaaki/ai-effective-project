対象シナリオ別に、人タスク → AIエージェントの役割分担を示す
本ドキュメントが扱うのは、典型的なマスター系エンティティ（ユーザーマスター・商品マスター・商品分類など）の CRUD と、その操作画面（一覧／詳細／新規登録／編集／削除）の実装。

# 商品マスター（products）

## 概要
店舗で取り扱う商品の基本情報を管理する。

## データモデル
| 項目          | 型             | 必須 | 一意 | 備考                              |
| ------------- | -------------- | ---- | ---- | --------------------------------- |
| id            | UUID           | ✓    | ✓    | サロゲートキー                    |
| code          | string(20)     | ✓    | ✓    | 業務キー。英数とハイフンのみ      |
| name          | string(100)    | ✓    |      |                                   |
| category_id   | UUID           | ✓    |      | 商品分類への外部キー              |
| price         | decimal(10,2)  | ✓    |      | 0 以上                            |
| description   | text           |      |      |                                   |
| is_active     | bool           | ✓    |      | デフォルト true                   |
| created_at    | timestamp      | ✓    |      | 自動付与                          |
| updated_at    | timestamp      | ✓    |      | 自動更新                          |

## 業務ルール
- code は半角英数とハイフンのみ、先頭はアルファベット
- price は 0 以上、上限 9,999,999.99
- 削除は物理削除。他テーブルから参照されている場合は拒否
- 同一カテゴリ内で name の重複は許可（エラーにしない）

## 画面構成
- 一覧画面 `/products`
  - 表示列: code / name / category / price / is_active
  - 検索: code, name の部分一致
  - ソート: code, name, price
- 詳細画面 `/products/:id`
- 新規登録: 一覧画面の「新規登録」ボタン → `/products/new`
- 編集: 詳細画面の「編集」ボタン
- 削除: 詳細画面の「削除」ボタン + 確認ダイアログ

## バリデーション
- code: 必須 / 20 文字以内 / 英数ハイフン / 先頭英字
- name: 必須 / 100 文字以内
- price: 必須 / 0 以上 9,999,999.99 以下
- category_id: 必須 / 商品分類マスタに存在すること

## 禁止事項（ステップ15で見つかったNGをここに追記していく）
- 一覧画面に「エクスポート」ボタンを勝手に追加しないこと
- 詳細画面に「コピーして新規作成」機能を勝手に付けないこと
- 「お気に入り登録」など装飾的な機能を追加しないこと
- 一覧画面に並び替えドラッグ&ドロップを追加しないこと
同等の内容を明記した「画面仕様書」「DB設計書」などが別途存在する場合、重複する部分は spec から削除して構わない。 その場合は spec から該当ドキュメントへリンクし、AI が参照できる状態にしておくこと。spec に残すのは 禁止事項 や、既存ドキュメントに含まれない補足ルールが中心となる。
業務ルール・バリデーション・画面挙動などが後から決まった場合は、必ず spec に追記すること。 追記後は AI に対して「更新後の spec を読み直し、差分を実装に反映する」よう指示する。
本タブが扱うのは、既存DBから条件指定でデータを抽出し、CSV／Excel／PDF などのファイルとしてダウンロードさせる画面の実装。 DB スキーマは既に存在している前提で、新規に作るのは 抽出ロジック と ダウンロード画面（絞り込みフォーム + ダウンロードボタン） の2つに絞られる。

  • 完了通知 → ダウンロードリンクの提示
  • ジョブ失敗時のエラー表示
▼ 開くステップ7 で失敗した場合の挙動
テスターAI が CI 実行結果から原因層を推定し、Orchestrator が該当AIへ差し戻す。修正後は依存ステップ以降が再実行され、再びステップ7 まで到達する。
失敗の症状 推定原因層 差し戻し先AI 戻るステップ／対応
絞り込みフォーム・ダウンロードボタン・進捗表示など画面挙動が仕様と異なる フロントエンド フロントエンドAI ステップ 4〜6 を再生成 → 6 のレビューループ → 7 再実行
ファイル内容（出力項目・絞り込み結果・フォーマット）が仕様と異なる バックエンド バックエンドAI ステップ 1 で UT を更新 → 2 で実装を修正 → 3 のレビューループ → 7 再実行
テストコード自体のセットアップ・期待値が誤っている（false fail） テストコード テスト実装AI ステップ 7 内でテストコードを修正 → 再実行
▼ 開くステップ8 でエンジニアが実施するテスト
簡単な動作確認
  • サイドメニュー → 画面表示 → 絞り込み入力 → ダウンロード の一連動作がスムーズ
  • 実際にダウンロードしたファイルを開き、表計算ソフト等で正しく開ける
  • 文字化け・列ずれ・改行コードの崩れが無い
  • 仕様外の絞り込み項目・余分なUI要素・想定外のボタンが追加されていないこと
  • NG 発見時は spec の禁止事項に追記し、AI へ反映指示
認証・権限
  • 未ログイン時のアクセスがログイン画面へリダイレクトされる
  • 権限のないユーザーが URL を直接叩いた場合のアクセス拒否
  • 権限の有無による画面メニューの表示／非表示の切替
  • 権限の有無によるダウンロードボタンの活性／非活性切替

▼ 開くspec の書き方例（売上明細CSVエクスポート） 
# 売上明細CSVエクスポート

## 概要
指定期間の売上明細を CSV ファイルとしてダウンロードする。

## 画面構成
- URL: `/exports/sales-detail`
- 絞り込み項目:
  - 対象期間 (from / to)   ※必須、最大 1 年間
  - 商品カテゴリ           ※複数選択可、未指定時は全件
  - ステータス             ※チェックボックス（確定／未確定）
- ダウンロードボタン: 「CSVダウンロード」

## 出力ファイル
- フォーマット: CSV (RFC 4180)
- 文字コード: UTF-8 BOM 付き
- 改行コード: CRLF
- ファイル名: `sales_detail_YYYYMMDD_HHMMSS.csv`
- 1 行目: ヘッダ行
- 区切り: カンマ
- 引用符: ダブルクォート（カンマ・改行を含む値のみ）

## 出力項目（順序固定）
| 列 | 項目          | 型       | 備考                          |
| -- | ------------- | -------- | ----------------------------- |
| 1  | order_id      | string   | 注文ID                        |
| 2  | order_date    | date     | YYYY-MM-DD                    |
| 3  | customer_name | string   |                               |
| 4  | product_code  | string   |                               |
| 5  | product_name  | string   |                               |
| 6  | category      | string   |                               |
| 7  | quantity      | int      |                               |
| 8  | unit_price    | decimal  | 円。カンマ区切りなし          |
| 9  | total         | decimal  | 円。カンマ区切りなし          |
| 10 | status        | string   | "確定" / "未確定"             |

## 業務ルール
- 削除済みレコード（is_deleted = true）は除外する
- 金額はすべて税抜
- 並び順: order_date 昇順 → order_id 昇順

## 上限と非同期化
- 同期ダウンロード: 最大 50,000 件まで
- 50,000 件を超える場合: 非同期ジョブに切替、完了後にメール通知 + ダウンロードリンク提示
- 100,000 件を超える場合: エラー表示し、期間を狭めるよう促す

## 権限
- 営業担当以上のロールのみアクセス可
- マネージャーロールは全社、営業担当ロールは自担当分のみ

## 禁止事項（ステップ8で見つかったNGをここに追記していく）
- 絞り込み項目に「店舗」を勝手に追加しないこと
- ファイル名にユーザー名を含めないこと（個人情報保護）
- 「Excel形式でダウンロード」など、spec に無い別フォーマットボタンを追加しないこと
同等の内容を明記した「帳票仕様書」「画面仕様書」などが別途存在する場合、重複する部分は spec から削除して構わない。 その場合は spec から該当ドキュメントへリンクし、AI が参照できる状態にしておくこと。spec に残すのは 禁止事項 や、既存ドキュメントに含まれない補足ルールが中心となる。
出力項目・絞り込み条件・上限値などが後から決まった場合は、必ず spec に追記すること。 追記後は AI に対して「更新後の spec を読み直し、差分を実装に反映する」よう指示する。

▼ 開くステップ5 で作成するテスト一覧（画面機能の網羅）
ナビゲーション
  • URL を直接入力して画面遷移できる
一覧画面（Read 系）
  • 初期表示でレコードが一覧に表示される
  • ページングが正しく動作する（次へ／前へ／ページ数）
  • 検索条件で絞り込める／空結果時の表示
  • 各カラムでソートできる（昇順／降順）
  • 件数表示（合計件数・現在ページ範囲）が正しい
  • 0件・1件・大量件数の境界で破綻しない
新規登録画面（Create 系）
  • 「新規登録」ボタンから登録画面が開く
  • 正常な入力で登録でき、一覧へ戻ると新レコードが見える
  • 必須項目未入力時にエラーが表示され、送信されない
  • 型／桁／フォーマットのバリデーション（メール・電話・日付など）
  • 業務ルール違反時のエラー表示（一意制約・関連必須など）
  • サーバー側エラー（重複・参照不整合）が画面に伝搬する
  • キャンセル時に入力が破棄され一覧に戻る
詳細表示画面（Read 系）
  • 一覧の行クリックで該当レコードの詳細が表示される
  • 全項目が正しい値で表示される
  • 関連エンティティへのリンクが機能する
  • 存在しないIDアクセス時に 404／適切なエラー表示
編集機能（Update 系）
  • 編集モードに切替でき、現在値が初期表示される
  • 変更を保存でき、詳細表示に変更後の値が反映される
  • バリデーション（登録画面と同じ観点）が効く
  • 楽観ロック（他者更新）競合時にエラー表示される
  • 編集キャンセルで変更が破棄される
削除機能（Delete 系）
  • 削除ボタン押下で確認ダイアログが開く
  • 「キャンセル」でダイアログが閉じレコードが残る
  • 「OK」で削除実行され、一覧に戻り該当レコードが消えている
  • 参照整合違反（他から参照されている）時に削除拒否＆エラー表示
▼ 開くステップ5 で失敗した場合の挙動
テスターAI が CI 実行結果から原因層を推定し、Orchestrator が該当AIへ差し戻す。修正後は依存ステップ以降が再実行され、再びステップ5 まで到達する。

# 商品マスター（products）

## 概要
店舗で取り扱う商品の基本情報を管理する。

## データモデル
| 項目          | 型             | 必須 | 一意 | 備考                              |
| ------------- | -------------- | ---- | ---- | --------------------------------- |
| id            | UUID           | ✓    | ✓    | サロゲートキー                    |
| code          | string(20)     | ✓    | ✓    | 業務キー。英数とハイフンのみ      |
| name          | string(100)    | ✓    |      |                                   |
| category_id   | UUID           | ✓    |      | 商品分類への外部キー              |
| price         | decimal(10,2)  | ✓    |      | 0 以上                            |
| description   | text           |      |      |                                   |
| is_active     | bool           | ✓    |      | デフォルト true                   |
| created_at    | timestamp      | ✓    |      | 自動付与                          |
| updated_at    | timestamp      | ✓    |      | 自動更新                          |

## 業務ルール
- code は半角英数とハイフンのみ、先頭はアルファベット
- price は 0 以上、上限 9,999,999.99
- 削除は物理削除。他テーブルから参照されている場合は拒否
- 同一カテゴリ内で name の重複は許可（エラーにしない）

## 画面構成
- 一覧画面 `/products`
  - 表示列: code / name / category / price / is_active
  - 検索: code, name の部分一致
  - ソート: code, name, price
- 詳細画面 `/products/:id`
- 新規登録: 一覧画面の「新規登録」ボタン → `/products/new`
- 編集: 詳細画面の「編集」ボタン
- 削除: 詳細画面の「削除」ボタン + 確認ダイアログ

## バリデーション
- code: 必須 / 20 文字以内 / 英数ハイフン / 先頭英字
- name: 必須 / 100 文字以内
- price: 必須 / 0 以上 9,999,999.99 以下
- category_id: 必須 / 商品分類マスタに存在すること

## 禁止事項（人間の最終確認で見つかったNGをここに追記していく）
- 一覧画面に「エクスポート」ボタンを勝手に追加しないこと
- 詳細画面に「コピーして新規作成」機能を勝手に付けないこと
- 「お気に入り登録」など装飾的な機能を追加しないこと
- 一覧画面に並び替えドラッグ&ドロップを追加しないこと
同等の内容を明記した「画面仕様書」「DB設計書」などが別途存在する場合、重複する部分は spec から削除して構わない。 その場合は spec から該当ドキュメントへリンクし、AI が参照できる状態にしておくこと。spec に残すのは 禁止事項 や、既存ドキュメントに含まれない補足ルールが中心となる。
業務ルール・バリデーション・画面挙動などが後から決まった場合は、必ず spec に追記すること。 追記後は AI に対して「更新後の spec を読み直し、差分を実装に反映する」よう指示する。

1. 概要

このドキュメントは、商品マスタ画面に data-testid を付与する方針・命名規則・実装例を定義します。 AI テストツール（Playwright MCP / Claude 等）がこのドキュメントを読むことで、コードを見ずにテストシナリオを先行生成できることを目標とします。

6. 重複レコード対策

商品名が同じレコードが複数存在するケースで、テキストだけでは行を特定できません。

解決策：data-row-id との組み合わせ

テーブル行に 2属性を必ずセットで 付与します。

// 繰り返し行に2つの属性を付与
<tr
  data-testid="product-table-row"
  data-row-id={item.id}          // エンティティID (ULID)
>

テスト側での選択方法

// ① nth() — 何番目の行か分かる場合
page.getByTestId('product-table-row').nth(1).click()

// ② data-row-id — エンティティIDが分かる場合（最も確実）
page.locator('[data-testid="product-table-row"][data-row-id="01JXXX..."]').click()

// ③ filter + hasText — 同名でも別列が違う場合
page.getByTestId('product-table-row')
  .filter({ hasText: 'PRD-002' })  // 商品コードは一意
  .click()
推奨優先順位： ②（data-row-id）> ③（hasText でコード列指定）> ①（nth）
nth は並び順が変わると壊れます。IDが使えるなら必ずIDを使ってください。

ページルートコンテナ（product/index.tsx）

  <header>

    <td>{item.productName}</td>

新規登録ドロワー（product-create-drawer.tsx）

<MultiLevelDrawer data-testid="product-create-drawer">
  <input
    data-testid="product-create-form-code-input"
    value={form.productCode}
    onChange={...}
  />
  <input
    data-testid="product-create-form-name-input"
    value={form.productName}
    onChange={...}
  />
  // ... 他フィールド
  <Button data-testid="product-create-form-submit-btn" onClick={handleCreate}>
    登録
  </Button>
</MultiLevelDrawer>

詳細ドロワー（product-detail-drawer.tsx）

<MultiLevelDrawer data-testid="product-detail-drawer">
  {!isEditing ? (
    <{/* 表示モード */}
    <Menu>
      <Menu.Target>
        <Button data-testid="product-detail-menu-btn">⋮</Button>
      </Menu.Target>
      <Menu.Dropdown>
        <Menu.Item data-testid="product-detail-edit-menu-item"
          onClick={() => setIsEditing(true)}>編集</Menu.Item>
        <Menu.Item data-testid="product-detail-delete-menu-item"
          onClick={handleDeleteClick}>削除</Menu.Item>
      </Menu.Dropdown>
    </Menu>
  ) : (
    <{/* 編集モード */}
    <Button data-testid="product-detail-edit-cancel-btn"
      onClick={() => setIsEditing(false)}>キャンセル</Button>
    <Button data-testid="product-detail-edit-submit-btn"
      onClick={handleUpdate}>更新</Button>
  )}
</MultiLevelDrawer>

8. Playwright テスト例

ページ識別・ナビゲーション確認

// ① 商品マスタページが開いていることを確認
await expect(page.getByTestId('product-page')).toBeVisible()

// ② ページタイトルで二重確認
await expect(page).toHaveTitle(/商品マスタ/)

一覧表示（行数・重複対策）

// 行数確認（20件 = デフォルトページサイズ）
const rows = page.getByTestId('product-table-row')
await expect(rows).toHaveCount(20)

// 特定行をIDで選択（同名レコードがあっても確実）
await page.locator('[data-testid="product-table-row"][data-row-id="01JXXX"]').click()

// 商品コードで行を特定（コードは一意）
await page.getByTestId('product-table-row')
  .filter({ hasText: 'PRD-001' })
  .click()

新規登録フロー

// 1. 新規登録ボタン
await page.getByTestId('product-header-create-btn').click()

// 2. ドロワーが開いたことを確認
await expect(page.getByTestId('product-create-drawer')).toBeVisible()

// 3. フォーム入力（ドロワー内にスコープを絞る）
const drawer = page.getByTestId('product-create-drawer')
await drawer.getByTestId('product-create-form-code-input').fill('PRD-TEST')
await drawer.getByTestId('product-create-form-name-input').fill('テスト商品')

// 4. 登録実行
await drawer.getByTestId('product-create-form-submit-btn').click()

// 5. ドロワーが閉じることを確認
await expect(page.getByTestId('product-create-drawer')).not.toBeVisible()

詳細表示 → 編集 → 更新フロー

// 1. 行クリック → 詳細ドロワー
await page.getByTestId('product-table-row').first().click()
await expect(page.getByTestId('product-detail-drawer')).toBeVisible()

// 2. メニューから「編集」
const detail = page.getByTestId('product-detail-drawer')
await detail.getByTestId('product-detail-menu-btn').click()
await page.getByTestId('product-detail-edit-menu-item').click()

// 3. 更新ボタンが表示されていること（編集モードの確認）
await expect(detail.getByTestId('product-detail-edit-submit-btn')).toBeVisible()

// 4. 更新実行
await detail.getByTestId('product-detail-edit-submit-btn').click()

削除フロー

// 1. 詳細ドロワーを開く
await page.locator('[data-testid="product-table-row"][data-row-id="01JXXX"]').click()

// 2. メニューから「削除」
await page.getByTestId('product-detail-menu-btn').click()
await page.getByTestId('product-detail-delete-menu-item').click()

// 3. 確認ダイアログが表示
await expect(page.getByTestId('product-delete-dialog')).toBeVisible()

// 4. 「削除する」で確定
await page.getByTestId('product-delete-dialog-confirm-btn').click()

// 5. ダイアログ・ドロワーが閉じることを確認
await expect(page.getByTestId('product-detail-drawer')).not.toBeVisible()

9. AI テスト生成ガイド

このセクションは テスト生成AI（Claude 等）が参照するコンテキストとして設計されています。 AIはコードを見ずにこのドキュメントだけでテストシナリオを先行生成できます。

ページ識別の手順

  1. data-testid="product-page" が visible → 商品マスタページである
  2. ドロワー系は data-testid="product-create-drawer" / product-detail-drawer" が visible で状態を判定
  3. 編集モードの判定：product-detail-edit-submit-btn が visible かどうか

テスト対象要素の発見アルゴリズム

// AI が画面を走査するときの優先順位
1. getByTestId('product-page')            → ページ確認
2. getByTestId('product-table')           → テーブルの存在確認
3. getByTestId('product-table-row')       → 行数確認・行選択
4. locator('[data-testid="product-table-row"][data-row-id="..."]') → 特定行
5. ドロワー系は対応する container testid が visible かを確認してから内部操作

AIへの指示テンプレート

使い方：このブロックをAIへのプロンプトとしてそのまま使用できます。 
以下の data-testid 定義に基づいて、商品マスタ画面の Playwright テストを生成してください。

【ページ識別】
- ページ確認: getByTestId('product-page')

【一覧テーブル】
- コンテナ: product-table
- 行: product-table-row (+ data-row-id="{エンティティID}" で特定)
- 同名商品が複数ある場合は data-row-id または商品コード(一意)で選択する

【検索フォーム】
- コンテナ: product-search-form
- 入力: product-search-form-{code|name|symbol|shipper|maker}-input
- セレクト: product-search-form-type-select
- ボタン: product-search-form-{search|clear}-btn

【新規登録】
- 起動: product-header-create-btn → ドロワー product-create-drawer が開く
- 入力: product-create-form-{code|name|symbol|shipper|maker}-input
- セレクト: product-create-form-type-select
- 送信: product-create-form-submit-btn

【詳細・編集】
- 行クリック → ドロワー product-detail-drawer が開く
- メニュー: product-detail-menu-btn → product-detail-{edit|delete}-menu-item
- 編集モード: product-detail-edit-{submit|cancel}-btn が現れる

【削除】
- product-detail-delete-menu-item → ダイアログ product-delete-dialog が開く
- 確定: product-delete-dialog-confirm-btn
- キャンセル: product-delete-dialog-cancel-btn

【スコーピング原則】
ドロワー内の操作は必ずコンテナを起点にスコープを絞ること:
  const drawer = page.getByTestId('product-create-drawer')
  await drawer.getByTestId('product-create-form-code-input').fill('...')

テスト生成の優先シナリオ

#シナリオ名検証ポイント
T-01ページ表示確認product-page が visible / タイトル確認
T-02一覧デフォルト表示テーブル行が20件以下 / ページネーション表示
T-03商品コード検索入力→検索→行数変化・該当行のみ表示
T-04検索クリアクリア後に全件表示に戻る
T-05新規登録（正常系）必須入力→登録→ドロワー閉→行が追加
T-06新規登録（バリデーション）必須未入力で登録→エラー表示・ドロワー開いたまま
T-07詳細表示行クリック→ドロワー開→正しい値が表示
T-08更新（正常系）編集モード→変更→更新→ドロワー閉→行に反映
T-09削除（正常系）削除メニュー→確認ダイアログ→削除確定→行が消える
T-10削除キャンセル削除確認でキャンセル→行が残る
T-11重複名レコードの特定同名2件存在時に data-row-id で各行を独立して操作
T-12ページネーション2ページ目への遷移→別レコードが表示

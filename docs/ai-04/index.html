顧客一覧画面 開発工数比較 (AsIs / ToBe)

要件定義済の状態から「顧客一覧を表示する画面」を作る場合の、設計〜実装〜単体動作確認までの工数を作業ごとに色分けして比較します。 工数は Claude Code の知見の範囲で見積もった値です。

※ 業界相場 (Capers Jones 等で「単体テスト後・統合前」概ね 5〜25件/KLOC) を踏まえ、 本シナリオでは人力 約10件/KLOC、AI駆動 約5件/KLOC を典型値として採用。 AI駆動では構文/型エラー・凡ミスは大きく減るが、 仕様の解釈ミスはむしろ起きやすい傾向 (暗黙の前提を読み取れないため)。

作業内訳 (h)

前提と注意点

  • 対象画面: 一覧表示・ページング・簡易検索を持つ典型的な顧客一覧 (CRUD の R 部分)。
  • AsIs: エンジニア 1 名が手動で実装する想定。レビュー・テスト記述・手戻りも含む。
  • ToBe: 本プロジェクトの「実装オーケストレーション」運用 (DB アーキテクト / バックエンド / バックエンドレビュワー / フロントエンド / テスターの各 AI による連鎖実行) に、エンジニアが要所で介入する前提。
  • ToBe では設計レビュー・仕様確定・最終動作確認はエンジニア工数として残るため、ゼロにはなりません。
  • UI が複雑/ドメイン固有のロジックが多い画面ほど、AI 駆動の効果は小さくなります。本見積りは標準的な一覧画面を想定。

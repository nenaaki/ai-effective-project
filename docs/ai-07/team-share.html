01　目指している姿

最終ゴールは「エージェント駆動型開発」

AIエージェントが 設計・実装・テスト を一連で自律的に進め、
人間は 「何を作るか」の判断 と 最終レビュー に集中する形を目指しています。

AIが担う

定型的な実装・テストコード生成・ドキュメント生成。手を動かす工程の大半。

人が担う

要件・業務判断、最終的な品質保証（レビュー・動作確認）。

ただし

いきなり全自動にはしない。相性の良い領域から局所的に積み上げる方針。

現在は Claude Code の「エージェント」「スキル」機能を使って、役割別のエージェント群（プランナー／実装／レビュー／テスト 等）を構築しながら進めています。

02　進め方

相性の良い領域から「局所的に積み上げる」

現在は マスタ画面やCRUD（一覧・登録・更新・削除） など、パターンが定型的で AIがレバレッジを効かせやすい領域から実証しています。

効きやすい領域

定型的・テキスト中心・標準パターンに近いもの。CRUD、マスタ画面、API実装、テストコード生成。実装工程は90%以上短縮することも。

効きにくい領域（人の判断が残る）

業務ロジックが厚い／視覚的な作り込みが必要／外部連携。業務固有の専門領域は人の判断比率が高い。

現在地：6/22「画面実装完了」マイルストーンに向けて進行中（理想線にほぼ沿うペース）。 → プロジェクト管理（進捗・WBS）

03　効果の測り方

「印象」ではなく〈想定〉と〈実測〉で比べる（As-Is / To-Be）

STEP 1

As-Is を見積る

実際にできあがったコード（プルリクエストの内容）をもとに、人間が手で実装した場合の想定工数を AIが算出する。

STEP 2

To-Be を実測する

プランナーに指示書(spec)を渡してから実装完了までの実時間に、人間のレビュー・動作確認・レイアウト調整の時間を加えて計測。

STEP 3

差分＝削減効果

両者の差を「削減効果」として提示。工程別に内訳も把握できる。

ポイントは 工程ごとに分けて測る こと。どの工程が縮み、どこが縮まないかが見えるため、 自チームへ適用する際の現実的な見積りに使えます。
→ 実例：AI駆動開発 実施レポート（画面別の As-Is/To-Be・工程内訳）

画面単位の削減効果

各画面の 総工数（全工程を合算） の比較。レビュー・動作確認はAsIs/ToBe両方に同じだけ含みます（＝下の補足の内訳）。
対象画面As-Is（通常）To-Be（実測）削減率
デポマスタ122 h27.4 h約78%
ユーザマスタ95.5 h20.5 h約79%
配送先詳細約6.2 h0.45 h約93%
配送完了登録約41.5 h4.0 h約90%
内訳の補足：上の削減率は 総工数ベースです。全工程が一律に縮むわけではなく、削減が効くのは 「実装・設計・テスト生成」工程（90%以上）。一方で レビューと動作確認の人間工数は通常開発と変わりません（AIが書いたコードを人が同じ時間かけて確認するため）。

05　課題は、つど運用で解消している

課題と対応

課題：要件・不明点まわり
① 要件不明確時のフロー — 業務判断が不明なとき、止める／確認する導線が未整備だった。→ 課題事例① problem_ex_1 ①' 不明点の切り分け — 不明点が「顧客確認／対象外／資料で定義」と混在し、整理に時間。→ 課題事例①' problem_ex_3
対応（運用）
1AIに仕様の不明点を出力させ Excelに集約。PM・他メンバーが回答する（すぐ回答できる／チーム内で決定が必要／顧客に確認が必要）。時間がかかるものは 期日を設定し、必要なら WBS化。
2実装は止めず、AIが行った 仮実装も記録しておく。
3仮実装からの修正・仕様変更に備え、各画面・機能の工数の 約30%を「修正対応工数」として確保（切り崩してタスク化）。AI駆動開発の進捗を常に可視化する（チケットの進捗を戻すことは禁止）。
課題：画面のつくり

② モックと実装の視覚差分 — レイアウトが乖離。画像での視覚比較が弱く検出に時間。

→ 課題事例② problem_ex_2
対応（運用）
レビュー・動作確認の中で乖離を見つけ出し、AIの補助を受けながら人間が手動で修正する。

付録　Q&A

導入を検討するときの論点（Q&A）

うちの業務でも同じ削減率が出る？
領域次第です。CRUD・定型パターンほど効きますが、業務固有の専門ロジックが厚い領域は人の判断が多く残るはず。まず小さい定型領域で実工数を測ってみるのがおすすめです。
現行版の所在・注意点は？
実際のエージェント定義やコード（Claude Code のエージェント／スキル）は PW案件のリポジトリにあり、この資料には載せていません。現エージェントには PW案件向けのカスタマイズが一部入っている箇所もあり、他案件で使う場合は多少の調整が必要になることがあります。
社内標準アーキ以外の言語・フレームワークにも対応できる？
可能です。AIDD の進め方自体は言語・フレームワークに依存しません。対象環境に合わせて CLAUDE.md（ルール・規約）と各エージェントを直せば、別の言語・フレームワークにも適用できます。
サポートは受けられる？
現時点では 自己責任での運用をお願いします。専任のサポート窓口はまだありません。共有する情報も暫定・開発途中のため、利用の判断（上司への相談含む）は受け取り側でお願いします。
全自動はいつ実現する？
目指してはいますが、今は局所的な積み上げの段階。実証で効果と課題を貯めている途中です。
